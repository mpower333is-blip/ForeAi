# Kempton Park Golf — Apple Watch (watchOS) app

A native SwiftUI watchOS companion that mirrors the Android **Wear OS** app
(`wear/`): a **standalone GPS rangefinder** for Kempton Park (bundled course, no
login/backend) plus the **on-wrist lightning safety alarm** and **next tee times**,
read from the same public Firestore snapshot the Wear app uses.

> watchOS is Swift-only — React Native/Expo does not run on the watch — so this is
> a separate native target. On Apple, the watch app **ships inside the iPhone app's
> build as ONE App Store submission** (unlike Android, where phone and Wear OS are
> separate uploads). So it goes to review **with** the iOS app, not on its own.

## What's here

```
ForeAiWatch/
  ForeAiWatchApp.swift   App entry (@main, SwiftUI)
  ContentView.swift      Rangefinder UI + club picker + tee times + lightning alarm
  RoundViewModel.swift   State, hole nav, distances, status polling, haptics
  Backend.swift          Reads clubs/kempton/public/watch via Firestore REST
  Course.swift           Bundled Kempton course + green GPS + club bag (ported from Course.kt)
  Geo.swift              Haversine distance in metres (ported from Geo.kt)
  LocationProvider.swift CoreLocation (when-in-use) GPS
  Models.swift           WLightning / WTee / WStatus
  Config.swift           Course id, event code, Firestore status URL (Kempton defaults)
  Info.plist             watchOS app plist (WKApplication, companion id, location usage)
```

Feature parity with the Kempton Wear OS build: GPS F/M/B distance to the green,
hole navigation, par + length, club bag distances, lightning alarm (buzz + full
screen), and the club's next tee times. Live score entry is intentionally omitted
(Kempton has no scoring backend — `Config.presetEventCode` is empty), exactly like
the Wear standalone build; it can be added later mirroring `Backend.kt`.

## Add it to the iOS app (one-time, on a Mac with Xcode)

The iPhone app is Expo-managed, so add the watch target to the **prebuilt** native
iOS project (it is regenerated by `expo prebuild`, so also add a config-plugin step
if you want it to survive a clean prebuild — see "Making it survive prebuild").

1. Build the native iOS project once: in `mobile/`, run
   `EXPO_PUBLIC_CLUB=kempton npx expo prebuild --platform ios`.
2. Open `mobile/ios/*.xcworkspace` in Xcode.
3. **File → New → Target… → watchOS → App.**
   - Product name: `ForeAiWatch`
   - Interface: **SwiftUI**, Language: **Swift**
   - "Watch App for" / companion: the existing **Kempton** iOS app.
   - Bundle id: `com.foreai.kempton.watchkitapp` (Xcode derives it from the phone's
     `com.foreai.kempton`).
4. Delete the placeholder files Xcode created for the new target, then **drag all
   the files from `apple-watch/ForeAiWatch/` into the target** (check "Copy items
   if needed" and tick the ForeAiWatch target). Use this folder's `Info.plist` for
   the target (Build Settings → Packaging → Info.plist File), or merge its keys
   into the generated one — the **`NSLocationWhenInUseUsageDescription`** and
   **`WKCompanionAppBundleIdentifier = com.foreai.kempton`** keys are required.
5. Set the watch target's Deployment Target to **watchOS 9.0+**.
6. Add an app icon for the watch in its `Assets.xcassets` (reuse
   `store/kempton/wear/wear-icon-512.png` / the club crest).
7. Signing: select the same Apple team as the iPhone app; let Xcode manage the
   watch app + provisioning profile.

## Build & submit for review

The watch app is embedded in the iPhone app's archive — submitting the iOS app
submits the watch app too:

1. In Xcode: **Product → Archive** (scheme = the Kempton iOS app, Any iOS Device).
2. **Distribute App → App Store Connect → Upload.**
3. In **App Store Connect**, the build now lists **iPhone _and_ Apple Watch**.
   Fill the watch app's **App Store screenshots** (Apple Watch series sizes — you
   can render them from the same mockups as the Wear images) and its description.
4. **Add for review → Submit.** One review covers both.

## Making it survive `expo prebuild` (optional, recommended)

A raw Xcode edit is wiped by a clean `expo prebuild`. To keep the watch target,
wrap the above in a small Expo **config plugin** (`withWatchApp`) that copies these
sources into `ios/ForeAiWatch/` and registers the target via `xcode`/
`@bacons/xcode` during prebuild, then reference it in `mobile/app.config.js`
`plugins`. Until that plugin exists, treat step-by-step Xcode setup as a one-time
action and avoid `--clean` prebuilds, or re-run the steps after one.

## Config

`Config.swift` holds the Kempton defaults:
- `defaultCourseId = "kempton-park"` — the bundled course card.
- `presetEventCode = ""` — standalone (no live scoring).
- `statusURL` — the Firestore REST URL for `clubs/kempton/public/watch` with the
  project's **public** Web API key (safe to embed; rules expose only
  `clubs/*/public/*` for read). This is the same snapshot the Wear app reads, so
  the lightning alarm + tee times are already live once the Firestore rules are
  published and the scheduled function has run.

For another club, change those three values (or read them from an `.xcconfig` per
scheme, mirroring how the Android build injects `WEAR_*` env vars).
